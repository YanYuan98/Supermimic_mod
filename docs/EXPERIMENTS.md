# 实验日志（EXPERIMENTS）

按时间顺序记录实测数据、偏离计划的决定和每个实验的结论。配置以 `logs/<run>/config.json` 为准。

## 2026-10-21 Phase 0–2：环境、数据、对拍

**环境（机器 A）**：1×RTX 5090 32 GB，驱动 580.178；Python 3.12；torch 2.14.1+cu130；mujoco 3.16.0；warp 1.18.0；mjlab 固定 commit 8bb2bc9。`uv sync` 一次成功。若系统 `PYTHONPATH` 带有其它 Python 版本的包（例如 ROS 的 python3.10 包），pytest 会加载到不兼容的插件而崩溃，运行 `uv run` 命令前用 `env -u PYTHONPATH`。

**数据**：
- 已从 HF 下载：`lvhaidong/LAFAN1_Retargeting_Dataset` 的 `g1/`（40 个 CSV，30 fps）；`bones-studio/seed` 的 `g1.tar.gz`（23.5 GB，未解压）。
- LAFAN1 转换后 40 条、2.451 h（论文 2.45 h ✓）。转换 40 条耗时 4 s（20 进程）。

**mjlab `csv_to_npz` 的 slerp 缺陷**：其 float32 `quat_slerp` 在相邻两帧四元数几乎相同时触发 `|dot−1| < 4·eps` 的提前返回，直接返回第一帧，导致重采样姿态最多滞后一个输入帧（walk1_subject1 上四元数最大误差 1e-3，角速度误差 0.056 rad/s）。我们的向量化实现与 scipy Slerp 一致到 1e-9；位置、关节、线速度与 mjlab 完全一致。因此 LAFAN1 npz 的参考角速度比 mjlab 自己生成的更平滑。

**可微 FK**：torch 位置 FK + 速度 FK 对 MuJoCo（`xpos/xquat`、`mj_objectVelocity(mjOBJ_XBODY)`）float64 下误差 1e-10，float32 下 2e-5。注意 `mj_objectVelocity(mjOBJ_BODY)` 给的是质心速度，`mjOBJ_XBODY` 才是链接坐标系原点速度（与 mjlab `body_link_*` 一致）。

**解析奖励**：8 个奖励项与 mjlab 的函数在 `sim.forward()` 后逐项一致，最大差 < 2e-5。观测头与环境观测（无噪声）逐元素一致（≤ 2e-5），历史布局为 term-major、项内时间优先、旧→新。

**仿真吞吐（Phase 0.3）**：4096 环境、真实 DR 配置（摩擦与 encoder_bias 按回合重采样、COM startup）、含 replay 记录器：**200,845 env-steps/s（20.4 ms/步）**；不含记录器 206,851。比计划的先验估计（1×10⁵）快一倍，记录器开销 3%。显存：4096 环境 + replay(1000 步) 共 2.9 GB。

**mjlab 适配中的问题**：`torch.cat` 直接作用在 mjlab 的 `TorchArray` 代理上会在 `__torch_function__` 里无限递归（列表参数未解包），取 `[:]` 得到普通张量即可。`mjlab.utils.torch.configure_torch_backends()` 默认开 TF32，对拍测试要先关掉。MuJoCo Warp 的 solver/linesearch 溢出提示通过 `wp_model.opt.warn_overflow=0` 无法关闭（掩码在建模时已固化），仅影响日志。

## 2026-10-21 速度优化与 BONES-SEED 数据

- `torch.compile`（default 模式）把一次想象 fwd+bwd（批 2048，H=32）从 1.48 s 压到 0.33 s（4.5×），编译约 210 s；世界模型 loss 的逐步函数同样编译。
- MuJoCo Warp 的 solver/linesearch 溢出 printf 是内核编译期常量（`wp.static(warn_overflow & ...)`），必须在 `put_model` 后、图捕获前置 0：用 `SimulationCfg` 子类重载 `apply_wp_opt`。未关闭时早期策略每步都触发 printf，e1b 的仿真步慢了 10 倍。
- 修好后（e1c）：100 次迭代 = 40 次更新 ≈ 24 s（仿真 2.2 s、WM 8 s、策略 13 s），约 0.5 s/更新，4096 环境、批 4096，显存 24 GB。

## 2026-10-21 漂移诊断（`scripts/diag_drift.py`）

整条 clip 确定性播放，逐步记录机器人锚点相对参考锚点的 xy 误差与 yaw 误差，并把机器人刚体速度按 yaw 误差旋转后重新计算速度奖励（去掉漂移成分）：

| | e7 论文观测 @20k | e3 +锚点 @24k |
|---|---|---|
| 平均 xy 误差 | **6.3 m** | 0.21 m |
| 平均 yaw 误差 | **82°** | 3.5° |
| xy 误差超过 0.3 m 的中位时间 | 7.7 s | 21.5 s |
| yaw 误差超过 15° 的中位时间 | 8.8 s | 72.7 s |
| 刚体线速度奖励（世界系 → 去 yaw 漂移后） | 0.12 → **0.83** | 0.86 → 0.87 |
| 刚体角速度奖励（世界系 → 去 yaw 漂移后） | 0.25 → **0.73** | 0.75 → 0.75 |

结论：论文观测的策略**局部跟踪质量与锚点策略相同**（去漂移后速度奖励 0.83 vs 0.87），评测差距全部来自全局漂移——纯本体策略没有 yaw/位置反馈，以约 1.7°/s 的系统性速率转偏，LAFAN1 的 clip 平均 **220 s**（102–273 s），9 s 后就已偏出 15°，之后世界系比较的四项奖励全部失效。

**协议上的关键事实**：BONES-SEED 过滤后 129,943 条 clip 中位长度 **5.8 s**、均值 7.3 s、90% 分位 12.6 s，只有 2.7% 超过 20 s。论文的主结果（Fig. 3a、Table A.8）都在这个基准上，漂移在这种长度上影响很小；而 Fig. 4a 的 LAFAN1 评测论文只写"每个检查点在全部 40 条 clip 上打分"，未说明是否整条 220 s 播放。我们按整条播放的 LAFAN1 结果（0.56）因此可能与论文的 LAFAN1 评测**不在同一协议**上，而 BONES-SEED 基准才是可比的。决定：直接上 BONES-SEED 论文口径全量训练（e8），以 2000 条子集与全量 benchmark 对照 Table A.8。

## 2026-10-22 v2：核查审阅后的修改（分支 `v2-improvements`，详见 `docs/IMPROVEMENT_PLAN.md`）

对照论文 PDF 与 `supermimic_vibed`（V，Isaac Lab 实现，LAFAN1 1.47 h 达到 0.829、0/40 失败）逐项复核后做出如下决定：

- **评测口径修正（F1）**：归一化回报的分母改为整条 clip 的步数（论文 §4："divided by the largest value this sum can take. A policy that terminates early therefore scores low"）。v1 的分母是存活步数，会高估带失败的检查点。上文 e2–e8 的数字都是 v1 口径；新 JSON 同时输出两种口径（`mean_norm_return` 与 `mean_norm_return_survived_v1`）。
- **目标中加入参考锚点相对朝向（F2）**：`anchor_obs` 改为三值 `none / ori / pos_ori`，默认 `ori`（6 维，IMU 可观测）。依据：论文写明跟踪接口沿用 BeyondMimic，正文只标注了两处改动（K=10 未来帧、Table A.1 的本体项）；mjlab 注册的 G1 跟踪任务是无状态估计版，它保留 `motion_anchor_ori_b`，只去掉 `motion_anchor_pos_b` 和 `base_lin_vel`。上文"统一论文观测口径（anchor_obs=False）"的决定因此撤销：`none` 改作对照组。
- **迭代 = 更新（F3）**：每次迭代先采 1/UTD = 2.5 个仿真步，再做 1 次 WM 更新（10 批）和 1 次策略/critic 更新；余弦学习率按迭代在 250k 内衰减到 0.03×，每 4000 迭代存检查点。v1 的 `iteration` 计的是仿真步。
- **目标函数不再除以 H（F4）**，以符合 Eq. 2 与 Table A.5 的裁剪工况。
- **critic 特权跟踪误差特征（F5）**：根误差 4、锚点相对位姿 9、14 刚体位置误差 42（锚点航向系）、关节误差 29，共 84 维，只进 critic。
- 可选项：`goal_features=traj`（F6）；`wm_warmup_iterations=500`（F7）；`amp=bf16`（F8）；MuJoCo Warp 溢出计数写入 TensorBoard 的 `sim/overflow_*`（F9）。

## 2026-10-22 v3：采纳 supermimic_vibed 中此前未采纳的部分

**提速（不改变算法，数值与旧实现逐元素一致）**：
- **批量 heads**：想象循环每步只做 锚点目标（只算骨盆→躯干 3 个关节的短链 FK）→ 策略 → 世界模型 → 观测，三者在同一个编译图里；全身 FK、奖励、终止、critic 特征在 rollout 结束后对 (H+1)·n 个状态一次算完。对照测试中状态、动作、奖励、存活率、critic 特征的误差都 ≤1e-6，梯度相对误差约 7e-8。想象 fwd+bwd 从 0.467 s 降到 0.186 s（批 2048，同卡同负载，**2.5×**）。
- 世界模型 8 步窗口整体编译；fused Adam；10 个窗口批次共用一次掩码计算；去掉每次采样的 host 同步。
- 整体吞吐 1.14 → **2.05 it/s**（同配置的真实训练，1.8×）。

**算法选项（均来自 vibed，v3 起为默认）**：世界模型输入/输出滑动均值方差归一化 + LayerNorm；解析软终止头；策略输入（观测历史与目标）滑动归一化 + ELU；想象起点距 clip 末尾至少 32 帧；关闭自碰撞；traj 目标特征。

## 2026-10-22 v4：新默认配置的最终验证（3 个种子 + 3 组消融，单卡 3 h）

GPU 1–6 各一组，从头训练，新代码，约 2.0 it/s：`v4-s0/s1/s2`（默认配置，种子 0/1/2）、`v4-selfcol`（打开自碰撞）、`v4-wmfixed`（世界模型恢复固定归一化、无 LayerNorm、学习的终止头）、`v4-polfixed`（策略恢复固定输入尺度、SiLU、无起点间隔）。结果见下节。

（格式：评测回报 / 失败 clip 数；括号内为终点迭代数。）

结论：
- **达到并超过论文水平**：默认配置 3 个种子在 3 h 时为 0.843 / 0.843 / 0.848，**全部 0/40 失败**（论文 Fig. 4a：单张 H100 1.2 h 达到 0.82；PPO-Sim 18 h 只有 0.60–0.72）。达到 0.82 的时间：三种子平均在 1.6 h 时为 0.809（最好 0.818），2.1–2.7 h 时全部超过 0.82。
- **训练效率**：本机约 2.05 it/s，1.6 h 约 12000 次迭代，与 vibed 达到 0.82 所需的迭代数（约 12000）一致。与论文 1.2 h 的差距主要来自宿主 CPU：这台 Xeon Gold 6530 负载下单核约 2.7 GHz，训练受 kernel launch 限制。按迭代数衡量，样本效率与 vibed 相当。
- **检查点之间的评测方差较大**：v4-s0 第 16000 次迭代掉到 0.721 / 9 失败，前后两个检查点都在 0.82 以上；训练回报、想象存活率、世界模型误差都没有异常。整条 clip（平均 220 s）、确定性评测对单次摔倒非常敏感，单个检查点的分数不宜过度解读。
- **消融**：到 3 h 时所有配置都在 0.83–0.85。策略输入归一化（+ELU、起点间隔）和关闭自碰撞**主要加快前期学习**（4000 次迭代时默认 0.67–0.74，对照 0.595 / 0.637），后期差别消失；打开自碰撞的终点反而最高（0.850）。世界模型的滑动归一化 + LayerNorm + 解析终止在各检查点上都没有可测的收益或损失（单种子）。
- **配置决定**：保留 v3 默认配置。理由：它是唯一做过 3 个种子验证的配置，三个种子终点都是 0 失败。世界模型选项保持开启，但记为"中性"；需要物理保真时（例如对照 BeyondMimic），可用 `--env.self-collision` 打开自碰撞，代价是前期慢一些。

## 2026-10-23 吞吐对比与 bf16 设为默认

同机、同时在 GPU 1–3 上各跑 1100 次迭代（前 300 次只训练世界模型；策略阶段为第 900–1100 次迭代的平均）：

| 配置 | 速度 | 每 50 次迭代耗时（仿真 / 世界模型 / 策略） | 策略阶段 GPU 利用率 |
|---|---|---|---|
| TF32，关闭自碰撞 | 2.06 it/s | 2.9 / 9.1 / 12.3 s | 约 71% |
| bf16，关闭自碰撞 | **2.68 it/s（+31%）** | 2.9 / 6.8 / 8.9 s | 约 73% |
| TF32，打开自碰撞 | 2.03 it/s（−1%） | 3.0 / 9.2 / 12.9 s | 约 73% |

与 vibed（3.1 it/s，RTX PRO 6000，bf16）的差距：约 30% 来自精度，其余主要来自硬件（GPU 的 SM 少约 10%，宿主 CPU 单核慢；策略阶段约有 30% 时间 GPU 空闲，在等 CPU 发 kernel）和 mjlab 环境流水线的开销（仿真约占 12%）。按迭代数衡量，两者的样本效率相同（约 1.2 万次迭代达到 0.82）。

决定：`amp` 默认改为 `bf16`（用户要求直接采用）。bf16 对精度的影响只有 v2 的单种子对照（3 h：bf16 0.810，TF32 0.803；8000 次迭代时 bf16 低 0.07），尚未在 v3 配置下用多种子验证。评测与部署脚本不设 autocast，策略以 fp32 推理（权重本身就是 fp32）。

- 2026-10-23：执行用的带噪动作截断到 ±20（`NoisyJointPositionActionCfg.noisy_action_limit`，与 vibed 一致）；观测和动作变化率惩罚仍用干净动作，评测（无噪声）不截断。
